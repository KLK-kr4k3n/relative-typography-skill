# 中英文、字重与空间的联动规则

本文所有数值均是试排起点，不是 Apple 或 W3C 为所有媒介规定的数值。来源与标准边界见 [research.md](research.md)。

## 字号与字面分别校准

字号 F 是 em 方框的大小；字面是在其中呈现的字形。不要用外接框高度完全相等作为中英匹配的唯一目标，也不要把拉丁 x-height 直接等同于汉字高度。先选协调的字体对，再判断是否需要 K。

建议使用同一段包含多种形态的样本：

> 信息层级与阅读节奏 / Information hierarchy and reading rhythm
>
> 北京、臺北與香港：2026 年第 3 季度，增长 12.5%。
>
> Typography: Ag, Hx, Il1, O0, 0123456789; UI / API / Wi-Fi.

在正文、分区标题和主标题各检查一次：汉字是否过黑；英文小写是否过弱；数字是否跳出；标点是否拥挤；英文升降部是否被裁切；字体缺字时是否换成明显不协调的 fallback。中文样本需覆盖目标地区实际字形。

如果相同字号下某个字体的视觉字面确实偏小，可以先做 0.95–1.05 的小幅试调；超出这个探索范围时重新检查字体选择和量度，不把范围当硬限制。K 应绑定到“字体对 + 角色/字号范围 + 输出环境”，不要绑定到中文/英文这一抽象标签。

混排一句话默认 K=1、共享基线；若必须修正某个 script run，使用明确的样式并重新检查整行行高。上下排列、同等重要的中英段落仍映射同一角色，不因英文较长自动缩小；可以分配更大宽度或更多行。

## 字重是相对等级，不是跨字体等值尺

|语义|初始字重意图|常见 CSS 提示值|视觉检查|
|---|---|---:|---|
|body / secondary / caption|Regular|400|小字不糊、不因浅色而消失|
|label / lead|Medium|500|操作可识别，长导语不要过黑|
|minor / section|Semibold|600|先与正文形成区别，再决定是否放大|
|title / display|Medium 或 Semibold|500/600|展示字体可以用 Regular；强调才到 Bold|
|局部强调|比当前重一级|按实际字体|不要一段全部变成强调|

工具只支持少数字重时，把这些意图映射到字体实际提供的字重；不要生成不存在的变量轴值。若渲染器发生合成粗体，应记录并优先换用真实可用字重。可变字体也要在合法轴范围内选择。浅字重、大字号与高对比度的品牌表达可以保留，但必须在目标阅读条件下成立。

同尺寸的 body 与 label 是刻意允许的：层级可以由字重、位置和留白建立。对于两个不同语义角色，若字号比小于约 1.12，可先检查是否会被误认为同一级；1.12 是审查提示，不是判错阈值。同角色轻微大小差异若没有功能依据，应合并 token。

## 行高使用文字自身字号；空间使用正文基准

|内容|试排行高 / 自身字号|适用条件|
|---|---:|---|
|短标签、按钮|1.25–1.45|同时给容器独立内边距，不用行高代替点击区域|
|英文长文|1.45–1.65|宽栏、长段落可偏松|
|中文与中英混排长文|1.55–1.80|重笔画、宽栏、较多标点时偏松|
|英文多行标题|1.05–1.20|检查升降部与强调样式|
|中文与混排多行标题|1.15–1.30|检查实际字面与多行节奏|
|多行小注释|1.40–1.60|不能为了塞下而过度收紧|

公式 `H=F×L` 中，L 相对该角色自身字号，而不是 B。例如标题 `2B`、行高 `1.2`，基线间距就是 `2.4B`。工具里的“行距增加值”与“总行高”可能不是同一参数，应确认 API 语义，避免重复加 leading。

空间的起点：

- 页边距先试 `1.25–3B`，再与现有网格、装订安全区或展示边界协调。
- 标签与值 `0.25–0.5B`，组件内边距 `0.75–1.25B`，相关组件间隙 `0.75–1.5B`，独立分区 `1.5–3B`。
- 长文段后间距先试 `0.6–1.0` 个正文行高；分区标题前距应大于后距。标题换行后以真实块高重新检查，不从首行基线估空间。

以上不是固定网格制度。若项目已经使用 4/8 等网格，先计算相对意图，再在不损害层级与可读性的范围内取整；文本字号、字距不必全部强行对齐空间网格。

## 内容宽度与密度

`x=C/B` 可描述容器能容纳多少个正文 em，但不是准确字数。中文长文可先试每行 24–40 字；英文 45–75 字符。窄移动端、分栏刊物、短说明可以低于这个起点，不需要为达到范围缩字。

若实测平均字宽为 `a×B`，每行字符数约为 `x/a`。汉字可先粗估 a≈1；英文应测实际样本，因为字体、大小写和内容会明显影响 a。使用 `ch` 只是在参考 0 的 advance，不能承诺某个 `65ch` 容器会正好放 65 个普通英文字符。

按目标行长 N 设计等宽多栏，先求单栏 `C≈N×a×B`，再判断总内容宽度 P 是否满足 `mC+(m−1)G≤P`。G 是栏间距，m 是栏数；不能先强行塞入固定栏数，再缩正文。超长英文单词、链接或代码单独配置断行或局部滚动。

布局密度优先改变组件间距、列数、内容呈现方式与标题对比。高密度不是把所有字统一缩小，低密度也不要求全体放大。caption 只是用途，不意味着关键错误、必要操作、核心数据都能缩成小字。

## 响应式与缩放的四种情况

|变化|正文基准|标题比例|布局动作|
|---|---|---|---|
|浏览器窗口变宽|通常保持|在选定区间内有限增加|限正文栏宽，增加列数/留白|
|窗口或容器变窄|通常保持|可取区间低端|换行、堆叠、减少列数|
|用户放大文字|尊重放大|可按语义适度压缩对比，但不能抵消文字放大要求|增高、重排、保留内容与功能|
|海报/展板的观看距离改变|重新校准|可以保留原比例起步|重算容量、减少密度、分阅读区|

若采用用户偏好专用缩放曲线，记录 `Fᵢ(u)=B₀×Sᵢ(u)×Rᵢ×Kᵢ`；`Sᵢ` 可随角色不同。此时不要再把已含偏好的 B 乘一遍 S。普通实现可让所有文字先跟随同一用户根字号，布局承担空间变化。

## 审查时看结果

核对标题是否抢过关键数据、英文翻译是否被无故降级、卡片是否各自使用不同的正文基准、标题孤字是否可通过栏宽解决、段落是否过宽、中文标点是否出现在不当行首行尾。不要只检查计算表正确就判定版式成功。

实际渲染至少覆盖正文、长标题、多行标签、数字、错误提示和真实注释。按任务需要检查地区字形、打印样张、投影或远距离观看；没有执行的验证如实列出。
