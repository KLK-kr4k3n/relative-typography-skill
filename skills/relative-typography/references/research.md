# 从 Apple Typography 到跨媒介相对排版

研究核验日期：2026-10-17。本文是研究与推导文档；本项目与 Apple 无隶属关系。为避免把观点误当规范，以下区分“来源事实”“数学推导”和“本包设计建议”。

## 1. Apple 真正提供了什么

Apple 的 [HIG Typography](https://developer.apple.com/design/human-interface-guidelines/typography) 以文字角色组织字号、字重和行高，并要求字号变化时布局仍清晰。其[官方 Markdown 原文](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/typography.md)可用于核验表格。本次已直接读取该原文，未使用第三方转抄表。

### 默认字号表的归一化

下表只取 iOS/iPadOS 的 Large 默认档。`R = 字号/17`，`L = 表中行高/字号`；比值为本项目计算，四舍五入。Apple 表头使用 Leading，本文按照其 WWDC20 对包含 leading 的 line height 的解释，将该列作为基线间距理解。它不是要额外叠加的一段空白。

|语义样式|原始字号 pt|表中行高 pt|R：正文=1|L：自身字号=1|
|---|---:|---:|---:|---:|
|大标题|34|41|2.000|1.206|
|标题 1|28|34|1.647|1.214|
|标题 2|22|28|1.294|1.273|
|标题 3|20|25|1.176|1.250|
|强调标题|17|22|1.000|1.294|
|正文|17|22|1.000|1.294|
|提示正文|16|21|0.941|1.313|
|次标题|15|20|0.882|1.333|
|脚注|13|18|0.765|1.385|
|说明 1|12|16|0.706|1.333|
|说明 2|11|13|0.647|1.182|

强调标题与正文同字号，前者常规状态为 Semibold，后者为 Regular。由此可以用“相同大小 + 不同字重”表达层级，无须不断制造新字号。[来源：HIG 字号规格](https://developer.apple.com/design/human-interface-guidelines/typography#Specifications)

### 跨平台与动态变化

macOS 的大标题/正文为 26/13；tvOS 的标题 1/正文为 76/29。前者大标题比值仍为 2；后者标题 1 比值约 2.621。角色、基准与平台一起决定结果，不能只按屏幕像素等比移植。[来源：HIG 平台规格](https://developer.apple.com/design/human-interface-guidelines/typography#Specifications)

动态字号也没有保持恒定比值：iOS 默认大标题/正文为 34/17=2，xxxLarge 档为 40/23≈1.739。标题与正文增幅不同，放大后主次关系仍可以保留。[来源：HIG Dynamic Type 表](https://developer.apple.com/design/human-interface-guidelines/typography#Specifications)

[WWDC20：The details of UI typography](https://developer.apple.com/videos/play/wwdc2020/10175/) 进一步说明，字号变化还牵涉光学尺寸、tracking、行高与按文字角色缩放的行为。这支持“文字样式是多维组合”的判断，不能把放大理解为单纯几何拉伸。

## 2. 从数据能推导什么

### 不存在由该表证明的通用固定公比

按正文向上取 17、20、22、28、34，相邻比值约为 1.176、1.100、1.273、1.214。它们不同，所以 Apple 的默认表不能证明“全页面统一用 1.25 公比”。1.2 或 1.25 可以是项目自己的选择，不能贴成 Apple 要求。

### 大标题约为正文两倍是一种有用锚点

iOS 与 macOS 上的这个相同关系可作为普通 UI 的初始参考，但不能推出所有标题、海报或语言都必须为两倍。更合理的迁移对象是“正文基准 + 角色比例 + 适应性布局”。本包 balanced 标题区间以 2 为宽栏端，正是这个推导的设计应用，不是原始表的完整复制。

### 行高也应按用途归一化

表中的 `22/17≈1.294` 是特定系统字体与 UI 场景的一项规格，并非中文长文或印刷书籍的普遍最优值。本包为多行中文正文建议更松的起始行高，是面向其他内容的设计假设；仍须用实际字体和阅读样本验证。

### “自重”在此按字重理解，但需区分视觉重量

字号指 em 尺寸，字面是字形在其中的视觉占比。相同字号的两种字体可能显得大小不同；相同的 500 字重也可能显得一轻一重。主次关系因此至少需要四个量：字号比、字重、字面/笔画表现、周围空间。这里不构造一个假装能量化审美的单一“视觉重要度分数”。

## 3. 为什么不能直接“页面宽度 × 百分比”

阅读条件与几何容量是两个不同输入。网页拉宽常常是增加栏数或留白，正文无须同步放大；A1 展板若比手持页看得更远，文字即使占同样页面百分比也未必可读。Figma 无限画布更没有一个可用来决定字号的全局页面宽度。

本包将其拆成：

```text
阅读情境 → 校准 B
页面/容器 → W/B、C/B、Cₜ/B
语义与密度 → 角色比例 R
语言与字体 → 光学校准 K、字重与行高 L
输出 → F=B×R×K，并渲染验证
```

若必须描述字号与页面的关系，可以导出 `F/W = R×K/(W/B)`。这是已校准结果的描述，而非独立的字号选择依据。

等比例放大实体页面且观看距离也按同倍率增加时，可以保留几何比例作为初始方案；若观看距离不变，未必需要同倍率放大文字。前提改变，就重新校准 B。用户视觉能力、材质、照明与字体也会影响校准。

对于已知距离 D 和视觉角 θ 的校准样本，字形高度满足 `h=2D×tan(θ/2)`。这个几何关系只保留样本的角尺寸；h 是字形实际高度，不是字体 em。没有可靠样本、字面系数和观看条件时，不用它生成“通用最小字号”。

## 4. 中英文不能只用一个换算系数

汉字通常以接近方形的字面组织，拉丁文字有 x-height、cap-height、升降部和比例字宽；这使同字号的视觉大小与文字密度可能不同。W3C 的[中文排版需求](https://www.w3.org/TR/clreq/)还涉及地区字形、混排与行首行尾标点等问题。该文档在本次核验时为 **2026-10-07 Group Note Draft**，属于工作草案，不是已获认可的强制标准。

本包因此采用“先 K=1，共同渲染，再对特定字体对校准”的策略。禁止默认把所有中文乘 1.1 或把所有英文缩成 0.8。字体替换、字重、字号层级与输出方式发生变化时，先前的 K 也可能失效。

字面匹配不等于一律把拉丁小写高度拉到汉字高度。比较完整句子的阅读灰度、数字、标点与节奏，选择协调的字体对，通常比调整大量局部字号更稳定。对应工具依据见 [CSS Fonts 4](https://www.w3.org/TR/css-fonts-4/)；`font-size-adjust` 和 `font-optical-sizing` 可以协助特定度量与光学尺寸，但不能自动解决跨文字系统的整体视觉匹配。该 CSS 规范仍在演进，实现时检查目标浏览器。

## 5. 本包的设计选择与证据边界

|选择|地位|理由与限制|
|---|---|---|
|语义角色组合字号、字重、行高|Apple 原始机制的抽象|保留角色而非复制平台 pt|
|正文归一化为 B=1|本包建模选择|便于跨单位计算，不保证 B 本身可读|
|compact / balanced / editorial / display|本包启发式|按阅读任务区分标题对比强度；允许覆盖|
|注释 0.82、辅助说明 0.90|本包启发式|比直接搬用 11/17 等更保守，仍要检查可读基准|
|标题容量 20B–60B 插值|本包算法|避免无限跟随宽屏增长；阈值不是实验结论|
|中英 K 初始为 1|本包工作策略|无失衡证据不改变字号；没有通用语言乘数|
|中文正文行高 1.55–1.80|本包试排区间|适用于正文起步，需真实内容验证|
|标题按行数与字宽拟合|几何预估|无法替代断词、标点和字体实际排版|
|展板按距离校准 B|跨媒介设计推导|需实体/等效条件验证，不能从画布推断实际距离|

这些参数没有经过人因实验验证，不声称是最优字号体系。实际品牌、字体、用户与内容有优先权；复用的是模型和验证方式，参数可以改。

## 6. Web 验证边界

- [WCAG 2.2 · 1.4.4 Resize Text，AA](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)：在条款适用范围内，文字可放大到 200%，内容与功能仍完整。不是允许把正常正文缩小后靠用户放大补偿。
- [1.4.10 Reflow，AA](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：横排纵向滚动内容以等效 320 CSS px 宽度验证重排；必要的二维内容有例外。不要把例外扩大到整个页面。
- [1.4.12 Text Spacing，AA](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)：在适用的标记语言与文字系统中，用户把行高调到 1.5 倍、段后间距 2 倍、字距 0.12 倍、词距 0.16 倍字号后，仍应保持信息与功能。这是覆盖压力测试，不是设计默认值。
- [1.4.8 Visual Presentation，AAA](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)：包括可达到每行不超过 80 字符/字形，CJK 不超过 40 的机制。不能把这个 AAA 条款中的一项误报为所有 UI 的 AA 强制行长。
- [1.4.3 Contrast (Minimum)，AA](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：颜色与对比度仍须单独检查；本包的相对字号不能自行证明 WCAG 意义上的“大文本”。不要仅根据角色名或 `R≥1.5` 就放宽对比度。

以上仅摘取与排版关系紧密的检查，不构成完整可访问性审计；WCAG 是 Web 标准，对非 Web 成品须按目标媒介另行判定。
